## Результати

Фінальні моделі обрано за val macro-F1 (15 % від `seg_train`, стратифіковано). `seg_test` (3 000 зображень) використано лише один раз, для двох фінальних моделей. Пристрій: Apple M2 Max, MPS (PyTorch 2.14, torchvision 0.29).

| Модель | Параметрів | Час навчання | val accuracy / macro-F1 | test accuracy / macro-F1 | Орієнтир з умови |
|---|---|---|---|---|---|
| A: власна CNN з нуля (4 VGG-блоки Conv-BN-ReLU ×2 + MaxPool, GAP, Dropout; `A_noaug`, обрана за val) | 1.2 млн | 15.5 хв | 0.911 / 0.912 | 0.904 / 0.905 | 75-85 % / 0.73-0.83 |
| B: ResNet18 (ImageNet), етап 1 із замороженим backbone, етап 2 з fine-tuning усієї мережі з lr 1e-4 (`B_full`) | 11.2 млн | 8.5 хв (разом з етапом 1) | 0.945 / 0.946 | 0.942 / 0.943 | 90-97 % / 0.89-0.96 |

Помилок на test: A 289, B 175 (−39 %). Повний прогін ноутбука зайняв ≈ 49 хв, бо паралельно працювали інші задачі. На вільній машині такий самий прогін займав ≈ 36 хв.

### Експерименти з оптимізації (бонус, порівняння лише за val macro-F1)

| Run | Що змінено | val macro-F1 | Час, хв |
|---|---|---|---|
| `A_aug` | CNN з нуля, аугментації (RandomResizedCrop, HFlip, ColorJitter) | 0.908 | 16.8 |
| `A_noaug` | CNN з нуля без аугментацій | **0.912** | 15.5 |
| `B_head` | ResNet18@224, навчається лише нова голова `fc` (етап 1) | 0.918 | 1.0 |
| `B_layer4` | етап 1 + fine-tuning `layer4` (етап 2, lr 1e-4) | 0.943 | 3.4 |
| `B_full` | етап 1 + fine-tuning усієї мережі | **0.946** | 8.5 |
| `B_head150` / `B_full150` | те саме на рідних 150×150 замість 224×224 | 0.900 / 0.938 | 0.8 / 4.3 |

Похибка val ≈ ±0.5 п.п., тому `A_aug` vs `A_noaug` і `B_layer4` vs `B_full` статистично не розрізняються. У попередньому (так само чистому) прогоні того самого ноутбука `A_noaug` зупинилася рано з 0.869, а `A_aug` мала 0.911. Навчання CNN з нуля на MPS не повністю детерміноване, і ефект аугментацій за 25 епох менший за розкид між запусками. ResNet-частина відтворилась до 4-го знака.

### Основні висновки

1. Transfer learning переважає: +3.8 п.п. test accuracy, на 39 % менше помилок, швидше навчання. Навіть лінійна голова на заморожених ознаках ImageNet за 1 хв (0.918) краща за CNN з нуля після 15-17 хв (0.908-0.912).
2. Fine-tuning додає +2.5 п.п. до замороженого backbone. Повне розморожування дає ще +0.3 п.п. (у межах похибки), вхід 224 замість 150 дає +0.75 п.п. (для замороженого backbone +1.75 п.п.).
3. CNN з нуля досягає ~90 % завдяки BatchNorm, GAP і зменшенню lr на плато, це вище орієнтиру 75-85 %. Без аугментацій вона сильніше запамʼятовує train (train 0.960 vs val 0.911).
4. Помилки зосереджені у двох семантично перекритих парах: `glacier ↔ mountain` (49 % помилок B) і `buildings ↔ street` (30 %). У датасеті є шум у мітках: 13 груп побайтових дублікатів з різними мітками (3 з них перетинають train/test, і B «помиляється» на всіх трьох), а серед найвпевненіших помилок B більшість має явно неправильні мітки.
5. Покращення (розділ 13 ноутбука): label smoothing / MixUp та очищення міток (confident learning), сильніший backbone (EfficientNet / ConvNeXt) і ансамбль, cosine-розклад з дискримінативними lr, TTA, довше навчання CNN з нуля з OneCycleLR.

## Як запустити

```bash
# з папки hw02-intel-image-classification
../.venv/bin/jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=-1 dz_topic_6_Джафарлі_Фарід.ipynb
```

* Дані. Ноутбук спершу шукає локальну папку `data/` зі структурою архіву Kaggle (`data/seg_train/seg_train/<клас>/…`, `data/seg_test/…`, `data/seg_pred/…`). Тут `data` є символьним посиланням на кеш kagglehub (`~/.cache/kagglehub/datasets/puneet6060/intel-image-classification/versions/2`), копії датасету в папці немає. Якщо `data/` відсутня (наприклад, у Colab), датасет завантажується через `kagglehub.dataset_download('puneet6060/intel-image-classification')`, а `kagglehub` встановлюється автоматично, якщо його немає.
* Ваги ResNet18 (`IMAGENET1K_V1`, 45 МБ) `torchvision` завантажує у `~/.cache/torch/hub/checkpoints/`. На macOS з Python від python.org можлива помилка `SSL: CERTIFICATE_VERIFY_FAILED`. Тоді запустіть `Install Certificates.command` з папки Python або завантажте файл вручну: `curl -L -o ~/.cache/torch/hub/checkpoints/resnet18-f37072fd.pth https://download.pytorch.org/models/resnet18-f37072fd.pth`.
* Пристрій обирається автоматично (CUDA → MPS → CPU). `NUM_WORKERS = 4`, на macOS з контекстом `forkserver`. Якщо виникають проблеми з multiprocessing, поставте `NUM_WORKERS = 0` (буде повільніше).
* Чекпойнти найкращих за val моделей кожного запуску ноутбук зберігає в `checkpoints/` (~5 МБ для CNN, ~45 МБ для кожної ResNet18). Після фінального прогону залишено лише дві фінальні моделі, `A_noaug.pt` і `B_full.pt`, решта відтворюється перезапуском. Здавати їх не потрібно.
* Залежності: `torch`, `torchvision`, `scikit-learn`, `pandas`, `numpy`, `matplotlib`, `seaborn`, `Pillow`, `kagglehub`, `jupyter`.
